      --blockedUrlPattern                           Restricts browser's network access by blocking specified URL patterns (uses https://urlpattern.spec.whatwg.org/). Silently detaches from targets with blocked URLs upon connection, and blocks runtime requests (including navigations and subresources); targets already open when patterns are updated via --watchConfig remain attached. Accepts an array of patterns. A pattern that uses a regexp group, a named group (`:name`), or a partial IPv4 wildcard (for example `(127\.\d+\.\d+\.\d+)`, `*://127.0.0.1::port/*`, or `*://127.0.0.*/*`) is rejected, because it is not enforced on redirects or subresources; use an exact value or a `*` wildcard instead. Patterns follow URL Pattern defaults: an omitted port matches only the scheme's default port (for example, `https://internal.corp/*` does not match `https://internal.corp:8443/`; use `https://internal.corp:*/*` to match any port), and the hostname must match exactly (a trailing-dot host such as `internal.corp.` is a different hostname).  [array]

Silently detaches from targets with unallowed URLs upon connection, and blocks runtime requests (including navigations and subresources); targets already open when patterns are updated via --watchConfig remain attached. Accepts an array of patterns. A pattern that uses a regexp group, a named group (`:name`), or a partial IPv4 wildcard (for example `(127\.\d+\.\d+\.\d+)`, `*://127.0.0.1::port/*`, or `*://127.0.0.*/*`) is rejected, because it is not enforced on redirects or subresources; use an exact value or a `*` wildcard instead. [array]

JPEG and WebP are ~3-5x smaller than PNG, which reduces transfer and storage size. [string] [choices: "jpeg", "png", "webp"] [default: "png"]

      --javascriptEvaluation                        Set to false to disable the server entry points for evaluating caller-provided JavaScript: evaluation tools (evaluate_script and slim evaluate) are disabled, the initScript parameter in navigate_page is turned off, and navigating to javascript:, data:, or vbscript: URLs is disallowed. This is not a JavaScript sandbox: page scripts and JavaScript triggered through other permitted browser interactions (e.g. clicks or typing) still run. If --experimentalDevtools is also enabled, the DevTools UI, including the Console that evaluates code in the inspected page, can be automated and is not restricted by this option. The client remains responsible for validating tool calls and parameters.  [boolean] [default: true]
      --fileNavigations                             Set to false to disallow navigating to file: URLs. When disabled, new_page, navigate_page and the slim navigate tool reject file: URLs, including view-source: URLs that target them. This restricts navigations the server performs. It is not a filesystem sandbox: it does not affect pages the browser already had open when the server connected, and the browser can reach the filesystem by other means. Use OS sandboxing for full filesystem confinement.  [boolean] [default: true]

Examples:
  npx chrome-devtools-mcp@latest --browserUrl http://127.0.0.1:9222                                                                       Connect to an existing browser instance via HTTP
  npx chrome-devtools-mcp@latest --wsEndpoint ws://127.0.0.1:9222/devtools/browser/abc123                                                 Connect to an existing browser instance via WebSocket
  npx chrome-devtools-mcp@latest --wsEndpoint ws://127.0.0.1:9222/devtools/browser/abc123 --wsHeaders '{"Authorization":"Bearer token"}'  Connect via WebSocket with custom headers
  npx chrome-devtools-mcp@latest --channel beta                                                                                           Use Chrome Beta installed on this system
  npx chrome-devtools-mcp@latest --channel canary                                                                                         Use Chrome Canary installed on this system
  npx chrome-devtools-mcp@latest --channel dev                                                                                            Use Chrome Dev installed on this system
  npx chrome-devtools-mcp@latest --channel stable                                                                                         Use stable Chrome installed on this system
  npx chrome-devtools-mcp@latest --logFile /tmp/log.txt                                                                                   Save logs to a file
  npx chrome-devtools-mcp@latest --help                                                                                                   Print CLI options
  npx chrome-devtools-mcp@latest --viewport 1280x720                                                                                      Launch Chrome with the initial viewport size of 1280x720px
  npx chrome-devtools-mcp@latest --chrome-arg='--no-sandbox' --chrome-arg='--disable-setuid-sandbox'                                      Launch Chrome without sandboxes. Use with caution.
